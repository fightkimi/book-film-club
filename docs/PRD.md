# 书影小组产品需求文档

版本：0.1　日期：2026-10-28　状态：开发基线

## 1. 产品目标

为定期开展读书、观影的小组提供一个完整循环：抽取主题、解构主题、推荐并确定作品、共同参与、记录评价、生成回顾、沉淀到书影库，再为下期活动提供依据。

核心对象是活动周期。主题、作品可以跨周期复用，成员的完成情况必须归属于具体周期。历史事实不能因为修改主题、作品或新周期规则而变化。

## 2. 已确认需求和实施假设

### 用户已确认

- 随机挑选活动主题，并由 AI 剖析、解构、推荐作品。
- 管理片库、书单、书评和影评，形成持续循环。
- 独立管理主题历史，按成员和周期管理完成情况。
- AI 先预留接口，稍后配置服务和密钥。
- 代码仓库为 https://github.com/fightkimi/book-film-club 。
- 视觉完整参考 https://www.rogerebert.com/ ，优先复用成熟 UI 组件。

### 第一版实施假设

- 单个小组、一套独立部署；管理员创建成员账号。暂不做公开注册、跨小组或社交平台登录。
- 周期为任意起止日期，支持多期并存；默认时区 Asia/Shanghai。
- 成员自报进度，管理员可以代为登记并留痕；不接管播放或阅读软件。
- 一个周期可选多部作品；完成规则在开始前确定，默认全部作品完成。
- 小组内共享活动评价和完成情况；个人笔记和收藏默认只向本人及授权管理员提供。
- 首轮交付以本地可运行、可持久化和可验证为边界。线上发布、域名、模型额度和生产运维需要另行配置。

## 3. 角色和权限

| 能力 | 管理员 | 成员 |
| --- | --- | --- |
| 主题维护、抽签、创建与发布周期 | 可操作 | 可查看 |
| 作品入库和提名 | 可操作 | 可操作 |
| 候选作品投票 | 每人每作品一票，可取消 | 同左 |
| 周期规则、截止日期、参与名单 | 草稿期可编辑 | 可查看 |
| 进度、评价、讨论参与 | 本人或代登记，记录操作者 | 仅本人 |
| 请假或不参与 | 可代登记 | 本人可登记 |
| 归档、活动回顾 | 可编辑、发布 | 可查看 |
| 成员账号管理、小组导出 | 可操作 | 不允许 |

账号标识唯一；禁用成员保留历史。所有写操作由服务端鉴权，不能通过改前端成员 ID 越权。

## 4. 用户流程和信息架构

主导航：活动、主题、书影库、成员、回顾。个人菜单：我的记录、修改密码、退出。管理员拥有新建、编辑和导出入口。

主流程：创建周期草稿 → 抽取或手选主题 → 选择讨论角度 → 推荐或提名作品 → 投票并确定作品 → 发布活动 → 更新个人进度和评价 → 结束活动 → 整理回顾 → 归档。

投票是决策参考，最终作品由管理员确认。没有配置 AI 时，依然能维护主题、使用预置的人工主题解构、手动选作品、完成活动和书写回顾。

## 5. 功能需求

### 5.1 主题库和抽取历史

- 字段：名称、说明、适用类型（读书／观影／书影联动）、讨论角度、问题、标签、抽取权重、状态、创建来源与时间。
- 状态：候选、暂不考虑；已使用由已发布活动推导，不与是否可抽取混为一个字段。
- 支持新增、编辑、搜索、按类型筛选，查看主题详情及关联周期。
- 抽取模式：换个口味（默认排除最近三期主题）、延续讨论（从用过主题中抽取）、完全随机（所有可用主题）。类型和停用条件始终有效。
- 权重为 1 至 10 的整数，默认 1；服务端使用随机源决定结果，转盘仅展示已确定结果。
- 每次记录完整候选 ID、权重、模式、操作者、时间与结果。重新抽取也会留下记录。
- 候选为空时解释原因，要求修改筛选条件，不偷偷回退到已排除主题。
- 主题使用历史来自实际活动；抽中但未采用只属于抽取历史。
- 开始活动时保存主题内容快照。之后编辑主题不会改变已开始或归档活动。

### 5.2 主题解构与 AI

- 围绕主题提供概念解释、2 至 4 个切入角度、各角度讨论问题、相关作品推荐及关联理由。
- AI 生成只产生草稿，经用户明确采用后才写入主题或作品库。
- 作品标题、作者／导演、类型、关联理由和来源链接分离；AI 提议默认标记“待核验”，不得冒充已验证资料。
- 支持主题候选生成、主题解构、活动回顾草稿三类任务。
- 服务配置仅在服务端；不在浏览器存密钥。采用兼容 Chat Completions 的接口，模型 ID 显式配置。
- 未配置时显示“尚未配置 AI”，保留手工路径；失败显示可重试提示，保留原始输入。
- 使用超时、响应体上限和 JSON 结构校验；模型输出是数据，不执行代码或命令。
- 回顾请求仅在管理员明确点击后发送本期共享评价，不发送登录信息或私人笔记。

### 5.3 周期活动

- 字段：名称、开始日、截止日、类型、主题快照、讨论方向、候选作品、最终作品快照、成员名单和完成规则。
- 状态：草稿 → 进行中 → 已结束 → 已归档。已结束允许补交；已归档只读。管理员可将已结束恢复为进行中。
- 发布要求：有效日期、至少一名成员、有效主题、至少一部作品且符合活动类型。
- 草稿可以修改范围和规则；发布后冻结主题、作品和完成规则，避免悄悄改变成员任务。
- 不根据日期自动跳转状态；逾期只是成员任务的事实标签。管理员决定何时结束、归档。
- 新成员不自动加入历史活动；草稿中明确选择参加名单。
- 归档不要求全部成员完成；未完成、请假和未参与保持原样。

### 5.4 成员完成情况

- 最小记录粒度：周期 × 成员 × 作品。记录进度 0～100、个人笔记、完成时间。
- 周期层记录参加状态（参加／请假／不参加）、讨论参与及其时间。
- 作品层书评／影评含内容、评分 1～5、剧透标记、创建及修改时间。
- 完成规则：完成全部作品或任选一部；可额外要求评价和参与讨论。
- 当要求评价时，所完成作品需有非空评价。任选一部模式要求同一部作品同时满足完成和评价，不能跨作品拼凑。
- 状态推导：请假／不参加优先；符合规则显示已完成或补交完成；未达标且超过截止日显示逾期；否则根据是否有活动显示未开始或进行中。
- 截止时间为截止日北京时间 23:59:59。完成时间是满足要求各项证据时间的最大值。
- 已结束允许补交，保留补交时间。已归档禁止修改进度和评价。
- 本期完成率分母只计参加成员，排除请假和不参加；分母为零显示“暂无参与成员”。
- 个人已读／已看不会自动完成任何周期任务。重复参加同一作品需要新周期记录。
- 提供周期完成表、成员跨周期档案及 CSV 导出；不做公开排名。

### 5.5 书影库和推荐

- 同一作品只建一份基础资料；按类型、名称、作者／导演去重；不同版本可在名称中标注。
- 字段：类型、标题、作者／导演、年份、简介、标签、参考链接、资料核验状态。
- 支持搜索、类型筛选、新增、编辑、查看关联主题、活动和评价。
- 草稿期支持提名、投票、最终选择，活动开始后投票锁定。
- 个人收藏状态：想读／想看、进行中、已完成；收藏与周期任务独立。
- 书影库不托管版权作品、不提供播放下载、不自动抓取豆瓣或微信读书账号。

### 5.6 评价与活动回顾

- 成员可创建或编辑本人每周期每作品的一篇评价；管理员代改需留审计记录。
- 剧透内容默认折叠，点击才展示。
- 回顾汇总主题、作品、完成统计和原始评价；AI 或管理员可以撰写总结。
- 总结内容与成员原文分开，不覆盖原文；共识和分歧不得在缺少原始证据时由模板虚构。
- 回顾保存时记录基于的数据版本；后续补交产生新版本，界面提示需要刷新总结。
- 归档保留最终汇总和发布时规则快照，仍可访问作品和主题来源。

### 5.7 账号、数据与导出

- 首次使用创建小组和管理员；无通用默认密码。成员账号由管理员建立，成员能修改密码。
- 密码使用带随机盐的慢哈希；会话使用 HttpOnly、SameSite Cookie，生产 HTTPS 启用 Secure。
- 登录尝试限频、会话过期、退出失效、修改密码撤销其他会话。
- SQLite 持久化；业务更新用事务和版本号防止并发覆盖。冲突提示刷新，不静默覆盖。
- 管理员可导出小组业务 JSON 和周期完成 CSV；不导出密码或会话。SQLite 备份恢复流程写入运行文档。
- 演示数据明确标为示例，只在用户主动选择后装载；不读取现有微信读书凭证或数据。

## 6. 设计基线

唯一视觉参考：RogerEbert.com。以实际捕获的页面和计算样式作为证据，记录桌面和手机的导航、标题、内容网格、文章／作品卡、筛选、搜索、页脚与交互状态。

完整复用其视觉规则，并以中文主题、活动和作品内容适配。原站未提供的管理表单、成员矩阵和抽签模块采用同一字体、间距、边框和交互风格。具体中文文本和管理功能无法与原站逐像素相同，验收区分“有对应原站模块”与“业务扩展模块”。

优先采用 Radix Themes／其底层成熟原语实现弹窗、下拉、标签页、输入与键盘交互；不自行重写焦点管理。图标依据源站实际证据选择，抽签复用 spin-wheel。用户明确指定的源站样式优先于通用 UI 技能中颜色、字号和边框默认建议。

保留来源记录，不把原站品牌名称冒充本产品品牌。素材和字体的再分发应依据其实际许可，无法复用的资产记录替代方案。

## 8. 技术设计

React + Vite 前端；Python 标准库 HTTP 服务 + SQLite，适用于本地及小规模单实例部署。生产阶段需 HTTPS 反向代理和备份策略；不将开发服务器直接暴露公网。

SQLite 保存账号、会话及带版本号的业务状态。业务状态包含主题、周期、作品、抽签、收藏、成员记录、评价、投票、回顾与审计。采用单事务读改写，服务端显式动作接口验证关系与权限。小组规模目标为数十人；不承诺多实例横向扩容。

核心 API：身份状态、初始化、登录／退出、修改密码、读取业务状态、执行业务动作、AI 草稿、导出。所有 JSON 写入要求同源检查和专用请求头；输出经 React 转义。

## 9. 验收标准

1. 可从空小组创建账号、添加成员并完成一次完整活动循环，刷新后数据仍在。
2. 同一主题与作品跨两期使用时，历史内容和各期成员进度相互独立。
3. 默认抽签排除最近三期，停用主题不出现；空候选明确报错；每次抽签有记录。
4. 修改当前主题和作品不能改变已发布周期快照。
5. 全部／任选、评价要求、讨论要求、请假、逾期、补交、归档锁定均有自动化用例。
6. 普通成员不能改别人的进度、规则、账号；未登录不能读取小组数据。
7. 未配置 AI 时核心流程可用；AI 失败及不合法响应不会污染已有数据。
8. 候选提名和投票可操作，发布后锁定；作品收藏不会自动完成周期任务。
9. 桌面和 390px 手机视口无横向溢出，弹窗支持键盘关闭、焦点管理，主要导航与操作可用。
10. 实际浏览器检查视觉与主要路径，自动测试和构建通过；差异和未验证项有明确报告。

## 10. 不在第一版范围

跨小组平台、支付、即时聊天、微信通知、日历推送、全网作品搜索、视频播放、微信读书同步、自动判定阅读完成、算法排行榜、多实例部署。主题抽取、周期管理、评价、收藏、回顾属于本版主流程，不能以静态展示代替。

## 11. 实施顺序与交付

1. 捕获源站视觉，固化产品与数据规则。
2. 实现持久化、权限、业务规则和自动测试。
3. 实现与源站对应的界面组件和完整业务交互。
4. 桌面／手机检查、核心流程测试、依赖检查。
5. 提供产品文档、设计记录、可运行代码、运行说明、验证记录和已知限制。

需求决策以本文为基线；实施中发生的范围调整需明确记录，不把计划能力标记为已完成。

## 12. 追加需求 作品信息与图片刮削

用户确认每本书、每部电影必须包含刮削资料和图片。书籍使用 Open Library 搜索和作品详情；电影使用 TMDB 搜索、详情、演职员与图片服务，TMDB 需要服务器配置读访问令牌。AI 密钥与元数据服务令牌独立。

导入流程：搜索名称或 ISBN → 展示多个候选及封面 → 用户确认作品 → 获取详情 → 预览 → 确认入库。无简介或封面的候选不能标为资料完整，需补充；不生成虚假海报或作品资料。ISBN 的版本选择需要保留来源说明，当前 Open Library 导入以作品级 ID 为主，版本级字段列为后续完善项。

存储来源名称、源作品 ID、来源 URL、抓取时间和原始补充字段。图片使用数据源返回的地址；书籍封面按 Open Library 官方要求直接引用 Covers API，保留来源链接。图片失败展示明确错误状态，可重新刮削或手动修正。

刷新元数据先展示预览；已有手工修订时禁止整条覆盖，改为手工合并。历史活动使用发布时快照，不随刷新改动。发布活动前检查作品标题、作者／导演、简介、图片地址、来源链接和人工匹配确认状态。

验收补充：成功导入真实书籍和电影的资料、封面；错误匹配可在预览阶段退出；无结果、超时、缺图、缺简介、电影服务未配置均有明确恢复路径；重复来源 ID 不新增重复作品。真实电影服务验收依赖 TMDB 令牌，未配置时不得宣称通过。

## 13. 追加需求 抽取动画和 Cult UI

- 读书主题以“主题书架”表现：候选主题显示为书脊，抽中主题对应的书滑出、落下并展开主题卡。
- 观影主题以“主题放映室”表现：屏幕亮起、简短倒计时，主题以片名字幕揭晓。
- 书影联动保留开源转盘表现。
- 服务端先确定并持久化抽取结果；前端动画只能揭晓结果，跳过、关窗、刷新不得产生第二次抽取。
- 动画约 2.7 秒；提供跳过，遵循系统减少动态效果。操作期间防止重复提交。
- Cult UI 已评估 Text Animate、Choice Poll、Loading Carousel。第一版直接适配 Text Animate 用于主题字幕，保留 MIT 版权；其余记录为可复用候选，不混入另一套完整组件体系。详见 COMPONENTS.md。

## 14. 最终设计修订

产品正式名称为“同频”。交付为响应式网页，手机操作按小程序式体验优化，不创建原生微信小程序客户端。

- Logo：细线条频率波形 + 手写“同频”，均为 SVG；不再使用人物、书页组合或放映机标志。
- 操作控件：按 Criterion 官网的直角矩形、平整底色、紧凑无衬线字、浅边框和反色悬停处理；移除金色、叠页纹理、书签切角和摄影机按钮轮廓。仍保留可见键盘焦点及至少 44px 手机点击目标。
- 收藏区：完整封面网格、紧凑标题、弱化作者信息、悬停／键盘聚焦操作，支持列表视图、排序及独立筛选面板。
- 主题卡：以与主题相关的经典电影海报作为背景，通过深色渐变与文字对比承载信息；不是胶片齿孔装饰。卡片标明视觉选片，主题详情可访问图片来源。内置六个策展关联，可在主题编辑中调整。
- 手机端：底部主导航替代多栏网页页脚；成员完成表转为纵向卡片；活动常用操作置于便于触达的固定区域；筛选使用完整面板。
